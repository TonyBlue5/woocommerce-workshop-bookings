1. Install and configure

  1. Back up WordPress files and the database. Use a staging copy for your first test.
  2. Install WooCommerce, configure currency, tax and payment methods, and create its Cart, Checkout and My Account pages.
  3. Extract the marketplace archive. Upload only plugin/workshop-bookings-pro-for-woocommerce.zip under Plugins → Add New → Upload Plugin.
  4. Deactivate any legacy or Lite edition before activating Pro. Keep only one edition active.
  5. Open WooCommerce → Workshop Bookings. Set reminder timing, calendar preferences and store location.
  6. Use WordPress Settings → General to select English or Ελληνικά. Product text remains merchant-managed.

Requirements: WordPress 6.4+, PHP 7.4+, WooCommerce 8.0+, a working cron runner and email transport. Use a currently supported PHP release in production. See the delivery test report for the exact versions actually tested. HPOS and legacy order storage use WooCommerce APIs.

2. Create a workshop product

  1. Create a simple, virtual WooCommerce product. Open its Workshop Booking panel.
  2. Enable single participation, monthly participation, or both, and enter prices.
  3. Add weekly schedule rows with weekday, start time, end time and capacity. Add blackout dates for holidays.
  4. Set visible future months, maximum months per booking and maximum participants. Save the product.
  5. Open the normal product page and choose sessions or months. Quantity represents participants. Multiple months multiply the monthly price.

Monthly purchases are prepaid selected months; this plugin does not automatically renew subscriptions or charge cards again. Monthly and single bookings share occurrence capacity. Existing order metadata remains the historical record when a schedule changes.

The workshop selector is designed for the standard WooCommerce product form. Test your theme, payment gateway and checkout customization on staging. Do not advertise compatibility with every theme or checkout extension without testing it.

Capacity and pending payments

New checkout requests reserve their places while payment is pending. Cancel abandoned pending orders to release these holds; use WooCommerce cleanup where applicable. Checkout and attendance changes share a database lock, and late payments recheck capacity before confirming a booking. If a gateway has already collected money and the place was reallocated after cancellation, review the order note and refund or reschedule manually. Administrator-created orders and manual status overrides require the merchant to check capacity.

Calendars

Customers can open a Google Calendar event link or download a signed .ics file for Apple Calendar and Outlook. No API key or Google Cloud account is needed. Google links save individual occurrences; the .ics download can contain multiple events. These are exports, not live two-way calendar synchronization. A later cancellation does not remove an already imported external event.

3. Attendance and reminders

Pro schedules reminders for paid occurrences and includes signed attendance links. Customers open a signed YES or NO link and confirm the response; opening a link alone does not change attendance. if enabled, declining releases that occurrence while preserving the rest of a monthly booking. Configure the response cutoff and reminder lead time. Keep WordPress salts stable because attendance and calendar links are signed.

WordPress cron must run reliably; configure a server cron on low-traffic shops. Mail acceptance does not prove delivery to the inbox. Test your email provider and spam handling. Lite sends basic reminders without attendance controls.

4. Loyalty and referrals

Open WooCommerce → Workshop dashboard. In Customers & loyalty, filter lapsed customers, export CSV and create a campaign for eligible past customers; optionally enter several recipient emails separated by commas. A reward coupon is restricted to its recipient email and one participant in one booking line. It is single-use and does not stack with other coupons.

Under Referrals, enable the program and choose the required number of friends, percentage, monthly allowance, booking mode, searchable workshop selection and expiry. Each group of eligible friends earns one coupon. A 100% reward for one month applied to a two-month purchase discounts one month's share for one participant.

Guest referrals

  1. The friend opens a personal referral link; an HTTP-only signed first-touch cookie lasts up to 30 days.
  2. At checkout the plugin saves the referrer, terms and normalized billing email to the order. The friend does not need to register.
  3. A completed paid eligible booking qualifies. Processing alone does not issue a referral reward.
  4. Self-referrals, repeated billing email, repeated account and invalid or expired cookies do not create extra rewards.

Prior paid customers cannot become new guest referrals. Terms are saved at registration or checkout. Partial qualifying-item refunds and full refunds revoke eligibility for unused rewards. Already redeemed discounts cannot be clawed back automatically. This is not identity verification; distinct fraudulent identities still require merchant review. Rewards are WooCommerce discounts, not cash commission payouts.

5. Design and send messages

Open WooCommerce → Message designer. Save a named subject and rich-text body using the native WordPress editor and media library. In a loyalty or cancellation campaign, select a saved template, customize it, review the preview and confirm the recipients. Saving a template does not send email.

Cancellation campaigns select a workshop and date. Confirmation adds a blackout, prevents affected checkout and suppresses reminders. Participants receive individual messages, and orders and payment records remain intact. Handle refunds separately in WooCommerce.

Messages are queued in batches using Action Scheduler with WP-Cron fallback. Delivery history distinguishes pending, sending, sent and failed. Retry failed messages; investigate a stuck sending record in mail logs before taking action, because it may have already been delivered.

6. Reports and customer accounts

Overview separates monthly and single booking lines and revenue by workshop and currency. Revenue is after discounts and item refunds, before tax and shipping. Date filters use order creation dates in the store timezone. Unallocated partial refunds cannot be assigned to a workshop; allocate refunds to order lines for accurate workshop reporting. Export overview and lapsed-customer CSVs from their respective screens.

My Account → My workshops shows a signed-in customer's own bookings, calendar details, attendance and earned coupons. A guest booking does not automatically appear in a newly created account by matching email alone. This prevents exposure of another customer's order history.

Admin tools require Administrator or Shop Manager access with manage_woocommerce; product-specific actions also check product-edit permission. CSV exports and mutations require a valid nonce. Customer reports do not infer marketing consent from a purchase.

7. Upgrade, switch editions and roll back

  1. Back up files and the database, including WooCommerce orders and plugin options/tables.
  2. Record current plugin and WooCommerce versions and a sample order's occurrence metadata.
  3. Deactivate the old edition. Install and activate the new edition; do not delete orders or reset settings.
  4. Compare old booking dates, capacity, prices and calendar links. Place a fresh guest and registered test order.
  5. Verify email jobs and My Account routes. If routes return 404, save Settings → Permalinks once.

Product/order _kwb_* metadata, settings, coupon records and the original referral table remain intact. Guest referrals use a new additive table. No uninstall routine deletes data. Returning to Lite disables commercial screens and jobs but retains commercial data for a later upgrade.

Pro's updater requires SHA-256 and an RSA signature from the existing publisher key. The test ZIP is a manual-install build, not a signed automatic-update release. Never replace the public key without an explicit key-rotation plan. Lite uses the standard WordPress.org update mechanism after directory publication and has no custom updater.

8. Support and acceptance checklist

Contact e-iT through it-e.gr. A dedicated support email and published documentation URL must be supplied before listing setup. Include versions, storage mode, theme, gateway and clear steps to reproduce; redact customer data and credentials.

  • Single, monthly and multi-month orders; mixed quantities and limited capacity.
  • Paid, unpaid, cancelled and refunded order states.
  • Guest referral, self-referral, repeat email, expired link and coupon redemption.
  • Actual email receipt, cancellation notices, attendance and .ics imports.
  • Administrator, Shop Manager, customer and anonymous permissions.
  • English and Greek desktop/mobile views in the target theme.
  • Legacy-to-Pro, Lite-to-Pro and Pro-to-Lite data preservation.
